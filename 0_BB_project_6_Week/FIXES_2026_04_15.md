## Проблема 1: Таймаут ожидания данных в main.py

### Было:
Функция `data_is_ready()` проверяла наличие данных за конкретную дату (`CURRENT_DATE - INTERVAL '10 days'`). 
Это приводило к таймауту, если в БД не было данных точно за этот день (например, из-за выходных или праздников).

**Код:**
```python
cur.execute("""
    SELECT EXISTS (
        SELECT 1 FROM quotes_gazp 
        WHERE date = CURRENT_DATE - INTERVAL '10 days'
    )
""")
```

### Стало:
Функция теперь проверяет **максимальную доступную дату** в БД и сравнивает её с текущей датой. 
Если разница не превышает 14 дней, данные считаются актуальными.

**Код:**
```python
cur.execute("SELECT MAX(date) FROM quotes_gazp")
max_date_result = cur.fetchone()[0]
days_diff = (datetime.now().date() - max_date_result).days
is_ready = 0 <= days_diff <= 14
```

**Результат:**
- Устранён таймаут ожидания данных
- Программа корректно работает с данными за любую доступную дату
- Добавлено информативное логирование последней даты в БД

## Проблема 2: Email не отправлялся при отсутствии сигналов

### Было:
В `email_notifier.py` при отсутствии новых сигналов программа просто завершала работу без отправки уведомления:

**Код:**
```python
if not signals:
    logger.info("Нет новых сигналов для отправки. Завершение работы.")
    return
```

### Стало:
Теперь при отсутствии сигналов отправляется email-уведомление (как это делает telegram_notifier):

**Код:**
```python
if not signals:
    logger.info("Нет новых сигналов для отправки. Отправляем уведомление об этом.")
    message_text = "ℹ️ Нет новых торговых сигналов.\nДанные проверены, сигналы отсутствуют."
    send_email_notification(message_text)
    return
```

**Результат:**
- Email работает как полноценный резервный канал для Telegram
- Пользователь получает уведомление даже когда сигналов нет
- Поведение email_notifier полностью соответствует telegram_notifier
